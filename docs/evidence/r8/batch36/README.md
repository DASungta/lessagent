# 定时任务工作区

「设置 → 定时任务」可为未绑定会话的任务保存三个工作区策略：使用项目根目录、按基准分支新建工作树，或使用项目已有 checkout。基准分支来自当前项目的 Git 本地引用，已有工作树来自该仓库报告的路径。新工作树可选择从远端更新起点。绑定会话的任务继续使用会话工作区。

Mate60Pro 使用隔离服务 T3 0.1.10，以 r5-round2 为验收仓库。测试专用本地分支和 Git 工作树在验收开始时由测试端显式准备。客户端只读取候选并保存定时任务设置。

| 操作 | 服务端回读 |
|---|---|
| 创建停用测试任务 | 项目根工作区。[初始配置](initial.json) |
| 指定测试分支和本地起点，在确认页取消 | 配置逐项等同初始值。[取消后](cancelled.json) |
| 确认保存新工作树 | `type=worktree`、实际测试分支、`startFromOrigin=false`。[确认页](newTreeConfirm.jpeg) · [回读](newTree.json) |
| 选择已有 checkout | `type=existing_worktree`，完整路径与实际工作树相同。[回读](existing.json) |

编辑页的「检查并保存」固定在底部。候选列表按项目、环境连接与读取代次隔离。分页达到上限时会提示可按分支名筛选。写前会重新读取候选、核对所属项目与根目录；未知的旧工作区对象在普通编辑时原样保留。任务未运行，因此实际定时触发后的 Git 启动路径仍待验收。

## 失效路径与恢复

隔离宿主的项目地址使用 /tmp，Git 报告当前 checkout 的规范路径使用 /private/tmp。界面与写前校验同时检查 Git 的当前分支标志和路径，候选中只保留真实的其他 checkout。

在最终包打开「已有工作树」确认页后，验收端移动了本次测试 checkout。手机点击保存时提示目标已变化，表单保留，提供「重新读取」。数据库仍为项目根策略，其他字段与初值相同。[失效提示](stale.jpeg) · [拒写回读](movedBeforeSave.json)

重新读取后，选择新路径 relocated 可正常保存，任务标题、计划等其他字段摘要仍与基线一致。[重选后回读](relocated.json) · [最终版工作区详情](finalExistingDetail.jpeg)
