在隔离服务 T3 0.1.10 和 Mate60Pro 上，使用[本地测试页](zoom-check.html)同时核对三件事：客户端回读的 CSS 视口、网页自行显示的 innerWidth × innerHeight、实际点中的按钮与计数。蓝色 NW 和 SE 位于页面不同角落。原始视口为 390 × 740。

|---|---|---|

| 150% | 260 × 493 | 新标签点 SE 显示 SE · 1。[截图](zoom150hit.jpeg) |

新建的第二个标签保持 100%，切回原标签仍读到 50%。页面操作能力、标签身份和连接代次均在写入前核对。新流在尺寸与帧确认后开启坐标输入。

## 验收中发现的两个问题

首次打开曾出现已取得控制权但画布为空。另一个只读媒体会话采到 CSS 390 × 740，JPEG 分别为 675 × 1280 和 780 × 1480，随后撤销该临时会话。尺寸比例匹配，不能据此确认空白的具体原因。[尺寸采集](stream-metadata.json)

从 50% 直接调回 100% 时，0.1.10 回报 390 × 740，网页实际仍为 780 × 1480，点击结果为 MISS。显式切换为另一固定尺寸后网页重新匹配。[初次复位失败](restoredHit.jpeg) · [改为另一尺寸后的画面](explicitResizeHit.jpeg)。前一张图是失败记录。

## 0.1.10 复位与最终安装

针对该版本，客户端在用户持有控制权且能精确还原固定或预设尺寸时，才提供兼容恢复。确认后设置缩放，临时改变一轴一个像素，再恢复原尺寸和预设标识。每步核对当前标签、控制权、连接和服务快照。它是多次 RPC，外部修改和断线仍可能打断操作。结果未确认时停止坐标输入，页面提示用户选择不同的固定尺寸并重新核对。该协议回读本身不能证明网页已经重排。

复位修复包从空标签输入 URL 点击「前往」即出现首帧，全程未点「重新连接」。新建标签首帧迟迟未到时，仅允许给当前标签重挂一次媒体，保留手动重连入口。手机将同一页面缩至 50%（780 × 1480），点击 NW 得到 1。先取消 100% 确认仍为 50%，再次确认后真实网页恢复 390 × 740，点击 SE 得到 2。保留下来的计数验证了页面状态与点击位置。[缩小后](final50hit.jpeg) · [复位后](final100hit.jpeg)

复位修复包 SHA-256 为 `3244f65f15b83fe142cfebc531fc03cbf74f15fbbce57f84f03b172096375712`，全量宿主回归 476/476 通过，失败、跳过、取消均为 0。特大字号可打开缩放菜单并选择档位。[真机菜单](largeMenu.jpeg)

## 超限补帧

手机视口缩到 25% 时，CSS 尺寸为 1560 × 2960。0.1.10 会交替传来 675 × 1280 的实时 JPEG 和 3120 × 5920 的静态补帧。[实际尺寸](stream-25.json) · [修复前](quarterFailed.jpeg)

新版在创建 PixelMap 之前释放超限图片资源并确认该帧，保留最后一张合规画面。等待合规帧期间暂停坐标输入，可换到其他支持的档位；连续三个原图尺寸超限会停止流并提示。压缩体积、解码失败、输出尺寸校验仍按原规则处理。在同一静态测试页实测，随后到来的正常帧恢复显示，点 NW 得到第 3 次点击。[25% 命中截图](quarterHit.jpeg)

最终安装包 SHA-256 为 `439de6f39b6fd105979b746ab624756232d27aee3a54e0c524620f8246df092e`。全量宿主回归 479/479 通过，失败、跳过、取消均为 0。

最终包把桌面 1280 × 800 调至 25%，收到 CSS 5120 × 3200 的合规帧。超限补帧使页面显示保留上一帧的提示，工具中的缩放仍可使用。直接换至 150% 恢复 853 × 533，再显式恢复 100%，实际网页为 1280 × 800；原页右下按钮累计 SE · 4。[超限时的工具状态](desktopQuarter.jpeg) · [桌面复位及命中](desktopRestoredHit.jpeg)

已恢复系统标准字号。尚待覆盖所有预设与填充模式组合、只读/多控制者真机竞争及长时间负载。0.1.10 的兼容复位只适用于可精确还原的固定尺寸或预设，仍有跨客户端并发窗口。
